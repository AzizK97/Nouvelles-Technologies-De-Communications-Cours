🏢 Architecture REST - Cas Ludo

Application de Commerce Électronique - Système de gestion des ressources

1. Contexte du Projet

L'entreprise Ludo, leader français de la vente par correspondance de jeux et jouets, met en place une application de commerce électronique avec les serveurs suivants :

🌐 Serveur Web (179.169.10.106) 📧 Serveur Messagerie (179.169.10.108) 🔍 Serveur DNS (179.169.10.107)

5. Règles de Filtrage et Accès

🛡️ Configuration du Pare-feu (Routeur R2)

Accès autorisés depuis Internet vers la DMZ :

  • Port 80 (HTTP) → Serveur Web (179.169.10.106)
  • Port 443 (HTTPS) → Serveur Web (179.169.10.106)
  • Port 53 (DNS) → Serveur DNS (179.169.10.107)
  • Port 25 (SMTP) → Serveur Messagerie (179.169.10.108)

Accès bloqués :

  • Port 22 (SSH) - Sauf depuis 195.65.21.4 (maintenance)
  • Port 23 (Telnet) - Totalement bloqué

9. Architecture Technique

📊 Flux de données

  1. Client Internet → Requête HTTPS vers https://ludo-club.fr
  2. Routeur R1 (80.160.65.107) → Transfert vers R2
  3. Pare-feu R2 (179.169.10.98) → Filtrage selon les règles
  4. Serveur Web DMZ (179.169.10.106) → Traite la requête API REST
  5. Communication interne → Le serveur Web communique avec:
    • Serveur SGBD (192.168.1.2) pour les données
    • Serveur Application (192.168.1.3) pour la logique métier
    • Serveur Fichiers (192.168.1.1) pour les images
  6. Réponse → Retour JSON au client via HTTPS

13. HATEOAS - Hypermedia As The Engine Of Application State

🔗 Principe HATEOAS

L'API fournit des liens vers les ressources associées, permettant aux clients de naviguer dans l'API de manière dynamique sans connaître préalablement toutes les URIs.

18. Conclusion

🎯 Points Clés

L'architecture REST mise en place pour Ludo offre une solution moderne, sécurisée et évolutive pour le commerce électronique:

  • Centralité des ressources: Chaque entité métier (produit, client, commande) est exposée comme une ressource accessible via des URIs standardisés
  • Sécurité multicouche: DMZ isolée, pare-feu R2, authentification JWT, HTTPS obligatoire
  • Performance optimisée: Liaisons 1Gbit/s, pagination, cache HTTP, compression
  • Évolutivité: Versionnement API, architecture modulaire, ajout facile de nouvelles ressources
  • Interopérabilité: Standards web (HTTP, JSON), compatible avec tout type de client (web, mobile, API tierces)

Cette architecture permet à Ludo de passer d'un modèle traditionnel de vente par correspondance à une plateforme e-commerce moderne, tout en maintenant la sécurité du réseau interne et en offrant une expérience utilisateur fluide.
