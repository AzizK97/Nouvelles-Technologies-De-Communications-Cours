🔄 Rappel : Qu'est-ce qu'un Système Réparti ?

Définition

Un système réparti est un ensemble de machines indépendantes qui apparaissent à l'utilisateur comme un système unique et cohérent.

Caractéristiques Clés

  • Concurrence : Plusieurs processus s'exécutent simultanément
  • Absence d'horloge globale : Pas de synchronisation parfaite
  • Pannes indépendantes : Une machine peut tomber sans affecter les autres
  • Communication par messages : Les machines communiquent via le réseau

⚠️ Défis des Systèmes Répartis

Défis Techniques

  • Latence réseau : Communication lente
  • Pannes partielles : Une machine tombe
  • Cohérence : Garder les données synchronisées
  • Concurrence : Gérer les accès simultanés

Solutions Existantes

  • Réplication : Copier les données
  • Consensus : Algorithmes (Raft, Paxos)
  • Load Balancing : Répartir la charge
  • Tolérance aux pannes : Redondance
💡 Point Clé : Les nouvelles technologies de réseaux visent à résoudre ces défis en rendant le réseau plus intelligent, flexible et programmable.

🎛️ Software Defined Networking (SDN)

Qu'est-ce que le SDN ?

Le SDN est une approche qui sépare le plan de contrôle (décisions de routage) du plan de données (transfert effectif des paquets).

🔌 OpenFlow : Le Protocole SDN

Principe de Fonctionnement

OpenFlow permet au contrôleur de programmer dynamiquement les tables de flux des switches.

Table de Flux (Flow Table)

Match Fields Priority Actions
IP src: 192.168.1.10
Port: 80		 100 Forward → Port 2
IP dst: 10.0.0.5
Protocol: TCP		 90 Drop
MAC: *
VLAN: 100		 50 Forward → Port 1

📌 Exemple : Premier Paquet

  1. Un paquet arrive au switch
  2. Aucune règle ne correspond → Envoi au contrôleur
  3. Contrôleur décide : "Forward ce flux vers port 3"
  4. Contrôleur installe la règle dans le switch
  5. Paquets suivants traités directement par le switch

📦 Network Function Virtualization (NFV)

Qu'est-ce que NFV ?

NFV consiste à virtualiser les fonctions réseau traditionnellement exécutées sur du matériel dédié (appliances).

Transformation

Fonction Avant (Hardware) Après (NFV)
Firewall Boîtier physique Cisco/Fortinet VM ou Container
Load Balancer F5 Hardware Appliance NGINX/HAProxy virtualisé
Router Routeur physique dédié vRouter (software)
IDS/IPS Snort sur appliance Snort dans un container

🔄 SDN vs NFV : Quelle Différence ?

Aspect SDN NFV
Objectif Rendre le réseau programmable Virtualiser les fonctions réseau
Cible Switches, routeurs (data plane) Appliances (firewalls, LB, etc.)
Architecture Séparation contrôle/données Virtualisation sur hardware générique
Protocole clé OpenFlow Pas de protocole spécifique
Origine Recherche académique (Stanford) Opérateurs télécoms (ETSI)

Complémentaires !

SDN contrôle le réseau, NFV virtualise les fonctions → Souvent utilisés ensemble

Exemple : Un contrôleur SDN peut orchestrer des VNFs (fonctions virtualisées) pour créer un service réseau complet.

Principe

Déplacer le calcul et le stockage plus près des utilisateurs/devices plutôt que tout centraliser dans le cloud.

14/25

🎯 Pourquoi l'Edge Computing ?

Problèmes du Cloud Centralisé

  • Latence : 50-100ms vers le cloud (inacceptable pour IoT, véhicules autonomes)
  • Bande passante : Coût élevé pour envoyer toutes les données au cloud
  • Confidentialité : Données sensibles envoyées loin
  • Fiabilité : Dépendance à la connexion Internet

Avantages de l'Edge

🚀 Latence Ultra-Faible

1-10ms (vs 50-100ms cloud)

💾 Économie de Bande Passante

Traitement local, seuls les résultats au cloud

🔒 Confidentialité

Données restent locales

⚡ Résilience

Fonctionne même sans Internet
